# Deployment preparation - GATE 4A

**Primary target: Railway, one long-running Node replica. Public release remains BLOCKED until shared storage, judge allowance and external HTTPS are verified.** No deployment has been executed.

## Current architecture

The production launcher is now `npm run start:public`. It sets NODE_ENV=production, validates public configuration before listening, binds 0.0.0.0 and respects PORT. The existing `npm start` remains loopback-only for local use. Node 24.13+ is required (server-side TypeScript scripts use native stripping). Build: `npm ci`, then `npm run build`; build without provider secrets.

package.json and the lockfile declare Node >=24.13.0 <25 so the hosting build selects the tested major version.

Identity HMAC signing now uses server-only TASTEPROBE_SIGNING_SECRET when configured. Use the same cryptographically random 32-byte value, encoded as 64 hex characters, on every instance. Production public mode requires it. The HMAC includes a movie-identity scope, exact identity and expiration; tampering, other keys and 30-minute expiry reject. Never put it in NEXT_PUBLIC variables or a client bundle. Local loopback development retains an ephemeral key when the variable is empty; production public mode cannot use that fallback. Rotate keys only deliberately: existing identities then need fresh human confirmation.

Audit tool sessions still reside in memory for 20 minutes (12 reservations/16 steps). The concurrent cap is 20, with expired sessions reclaimed. A restart loses session/proposal state, but does not silently reuse another analysis. Download Passports before maintenance. No filesystem stores durable user/session state. Shared quotas and stable identity signatures do not make tool sessions distributed. **Vercel/multiple replicas are not supported for the complete Audit/Rescue workflow yet.**

## Shared atomic consumption control

The dependency-free adapter uses Upstash REST POST with one Redis EVAL to check and reserve total, provider-minute, client-minute and operation-minute counters atomically. All keys share one namespace/hash tag. Totals never expire; minute windows expire 60 seconds after first admission. Each real upstream attempt is reserved before fetch, including failures; no automatic retry/refund. Qloo and TMDB are independent. Authentication/quota HTTP 401/403/429 persist a provider halt key until deliberate operator review. Redis errors, timeout, malformed response, missing config or quota exhaustion cannot authorize a provider call. A lost reservation response may conservatively count a request that was never sent.

| Layer | Global per minute | Per client per minute | Per client/operation per minute |
| --- | --- | --- | --- |
| Qloo | 12 | 6 | Search 4; Insights 2 |
| TMDB | 60 | 20 | 20 |
| Cost-capable HTTP routes, including tool-session creation | 120 | 20 | 10 |

Provider total caps come only from the required environment values. Existing local process/session caps remain as additional conservative bounds, not shared guarantees. The HTTP guard also has a one-million lifetime admission safety ceiling. 429 includes Retry-After: 60; total/halt exhaustion needs operator action, not repeated Retry. No quota/state reset endpoint is exposed.

All counters for a client use an HMAC identifier, not a stored raw IP. With no verified trusted IP header, every caller shares the anonymous bucket. This is deliberately conservative but may limit concurrent judges: configure a trusted ingress or schedule the small demo accordingly. Never trust x-forwarded-for from arbitrary clients. The application does not establish that Railway overwrites a particular IP header; verify the actual ingress before enabling it. An external WAF/bot policy is still recommended to protect the Redis service itself and provide fair access under distributed abuse.

## HTTPS and external verification

Public POSTs require Host exactly equal to the configured public authority and Origin either absent for non-browser agents or exactly the configured HTTPS origin. Cross-site Sec-Fetch-Site is denied. Internal HTTP reconstruction by the reverse proxy is accepted only with the explicit configured external Host. Forwarded-host/proto headers cannot authorize an origin. No wildcard or insecure browser origin is allowed. No auth cookie was introduced.

Check the real hostname after domain assignment; HTTP tests emulate this contract but are not an actual Railway proxy test. Public requests without complete quota/signing configuration fail closed. Routes are fixed-host and cannot fetch arbitrary user/model-selected URLs. GET /api/health remains CONFIGURED_NOT_VERIFIED rather than a claim of LIVE success. No hosted secret/admin operation is exposed.

After separate publication approval, run these non-provider checks against the actual domain:

```powershell

curl.exe --fail --show-error "$demoOrigin/api/health"

curl.exe --silent --show-error -X POST "$demoOrigin/api/entities/search" -H 'Content-Type: application/json' -H 'Origin: https://unauthorized.example' --data '{"query":"Arrival"}'
```

Expected: configured health without LIVE assertion, /review 404, foreign-origin 403 without provider invocation. Health should be BLOCKED_LIVE if the Qloo key is missing. Do not perform an allowed Search/Insights until a new budget is explicitly approved. Then complete one Discover and one Audit browser flow, including downloads and public-origin CSRF checks, on the actual HTTPS origin. Never use fixtures to claim public LIVE success.
